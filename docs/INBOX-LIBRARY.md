# Inbox and Library

Settings has independent Inbox and Library paths. They must be absolute, writable, unlinked, non-overlapping folders. Saving creates missing folders after validation. Changing a setting never relocates existing books. Inbox defaults to `inbox` under the application directory; Library keeps its existing default. There is currently no settings export/import feature to migrate.

Library Manager uses the same Cover, List, and Edit views for both roots. External and standalone projects remain available through **Workbench projects**. Startup and **Refresh** reconcile both roots asynchronously. Scans compare audio and metadata paths, sizes, and modification times; unchanged books reuse cached metadata. They do not transcribe, decode audio, or regenerate waveforms. Working directories and linked directories are excluded.

Named book folders are scanned independently, even when their parent contains loose audio or `metadata.json`. Numbered CD/disc/chapter folders stay together. Loose books in a collection are separate entries; matching multipart filenames, such as `Book (1 of 2).m4b` and `Book (2 of 2).m4b`, stay together. Sidecars take precedence within a book, followed by embedded tags, project metadata, and folder/file names. Ambiguous layouts or missing metadata need review. A small red marker explains identification uncertainty. Book existence comes from disk; missing books leave the root view while their project records remain recoverable. Refresh also replaces old automatic collection entries with separate books, retaining the original project data for recovery. Explicitly selected membership is preserved. If an entire root is unavailable, records are retained and a warning is shown.

The wrench means there is no current successful final check. A green check records a SwissMouse PASS with source/export file signatures. Material filesystem changes or stale processing results invalidate completion. Existing projects without this evidence require another final check. These workflow fields stay in SwissMouse's existing `jobs.json`; Audiobookshelf sidecars remain compatible.

Inbox projects using the default output location stage new exports under the Inbox's hidden `.swissmouse-work` directory. Explicit project output locations remain supported. After a successful final check, **Move to Library** is available in Final Check and on completed Inbox books in Library Manager. Both open the same dialog and use the same transfer service:

- **Copy & Keep** copies the completed project and keeps every original file and folder.
- **Move & Clean Up** copies and verifies the project, saves its Library paths, then removes only the associated originals. Files referenced by other projects are retained.
- **Cancel** closes the dialog without filesystem changes.

The configured Library folder pattern determines the destination. The manifest contains selected source audio, successful exports, registered metadata/cover/chapter sidecars, and saved book metadata/artwork. Separate outputs retain the existing `Finalized` layout. It excludes unassociated files and processing caches. Folder scans may establish ownership of conventional sidecars only for an unambiguous book whose audio is already attached; shared folders never confer ownership of all their files. Named sidecars can be stored explicitly in the project's `associatedFiles` manifest. New metadata exports and selected source covers register their paths there.

Copies use exclusive destination reservation, file counts, sizes, and SHA-256 verification. Existing destination folders are never overwritten. A failed transfer or failed project save leaves originals intact and does not mark the transfer complete. Cleanup verifies the whole transfer before deleting anything, rechecks each file, and journals each recoverable file rename before deletion. Source cleanup uses file removal and non-recursive `rmdir` only: hidden files, unrelated files, and non-empty folders remain, and configured roots are never removed.

The stable project ID, metadata draft, chapters, and processed state follow the Library copy. Both views update automatically. Kept originals remain associated with that project in `retainedSourceFiles`; unchanged originals are excluded from rediscovery on Refresh, Rebuild, and restart. A replaced or changed original can be discovered again. A partial cleanup reports a warning while keeping the verified Library copy and any remaining originals.

An interrupted transfer has a recovery journal. On startup an uncommitted transfer keeps its originals and retains destination files in a hidden recovery folder. Interrupted per-file cleanup restores its quarantined original without overwriting an existing file. Recovery never automatically deletes remaining originals. Older folder-based move journals remain supported. Recovery locations and skipped shared files appear in the technical log.

Scan summaries, identification uncertainty, completion changes, move verification, failures, and recovery appear in the existing master technical log. No continuous folder watcher runs; press Refresh after changing files externally.
